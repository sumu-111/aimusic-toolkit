## 四、代码框架

### 4.1 分层架构

```
┌─────────────────────────────────────────────┐
│ 调用方（前端，未开发 / curl 测试）             │
│   HTTP :8787（CORS 已开，浏览器版兜底可用）     │
├─────────────────────────────────────────────┤
│ worker.py  IPC 服务端（Flask）                │
│   /analyze → analysis.py                    │
│   /parse_intent → agent/intent.py           │
│   /execute_plan → pitch.py                  │
├─────────────────────────────────────────────┤
│ analysis.py 音乐分析层                        │
│   beat.beat_track → bars（小节，失败降级整段） │
│   pyin → pitch 轨迹 + 置信度 + 结果缓存        │
├─────────────────────────────────────────────┤
│ agent/ Agent 层（双通道）                     │
│   LLM（JSON Schema 约束）→ 规则模板兜底        │
│   → preflight 预检（track/时间/参数/锁定）     │
├─────────────────────────────────────────────┤
│ pitch.py 修音引擎                             │
│   裁切窗口 → 分段 → Phase Vocoder → 合成回写   │
│   → 重检测 → before/after 偏差曲线            │
│   → verify_wav 字节校验 → WAV 导出            │
└─────────────────────────────────────────────┘
```

### 4.2 数据流（一条指令的旅程）

```
用户输入"只把人声第 3 小节高音修准"
  → /parse_intent（LLM 或规则模板）
  → plan {op, track, start_sec(来自小节坐标), end_sec, mode, strength}
  → preflight 校验（越界/超参数/锁定 拒绝）
  → 前端确认（未来）→ /execute_plan
  → pitch.py: pyin 检测 → 逐音符分段（跳变>0.5 半音切分）
  → 每段：目标=最近半音 → shift×strength（≤±2 半音守卫）
  → librosa pitch_shift（Phase Vocoder）→ 拼接回原音频
  → 重检测 → {before_cents, after_cents, curve, output_path, wav_check}
```

### 4.3 关键设计决策（答辩可用）

1. **坐标来自分析层，LLM 不猜时间**：`start_sec/end_sec` 由小节定位给出，LLM 只做意图映射——对应方案核心卖点"音乐分析层 grounding"
2. **统一离线渲染**：预览即渲染结果，无第二套实时图，从根上避免"预览与导出不一致"
3. **守卫策略**：低置信段（<0.15）跳过保留原声、全部无效才拒绝——既保"绝不静默硬改"，又不误杀真实人声（pyin 对真人声置信度仅 0.2~0.8）
4. **双通道 Agent**：LLM 失败/断网自动降级规则模板，同一 UI 同一 plan 字段
5. **兜底三级**：16kHz 降采样（超时）→ 兜底渲染预生成（现场）→ 错误码回退（失败）
6. **回退即文件**：每次渲染生成新 WAV 文件，历史天然分支式（借鉴 TuneFlow pipeline 思想，见《参考项目借鉴点清单》）

### 4.4 可扩展点（加分项入口）

- **多轮修改**：`parse_intent` 已接收 `project_state`，接入历史即可
- **模板保存**：plan JSON 即模板，可序列化复用
- **Demucs 去人声**：作为前置节点接入 worker（当前明确不做）
- **真实 LLM 通道**：`agent/intent.py` 已实现 OpenAI 兼容调用，配 Key 即用
